# Fidelity checks against the original (DOSBox-X)

Method: `docs/DOSBOX.md`. Capture the emulator window, reduce it to 640x480, diff with `cargo run --release -p mad-app --example refdiff -- <capture> <mine> <diff.png>` (red = channel difference > 24). The original runs in video mode 2 (8-bit, `ICONS2`) for these checks: set byte 0 of the working copy's `CONFI2/CONFIG.DAT` to 2.

## Start menu (2026-11-06, first real comparison)
| step | differing pixels |
|---|---|
| before | 5.05 % (titles gold, black corners round the parchment window, text too narrow) |
| after | 2.06 % |

Found and fixed:
- Titles `^ ... _` and their ornaments are **dark**, not gold (gold only for hovered items).
- Frame tiles `05-11`: palette index 0 is **transparent**; the corners showed black.
- Every glyph except the space advances **one pixel more** than the file's advance table. Letters in the middle of lines match exactly; the line ends are still 1-2 px off for some glyphs (line 2 is 4 px too wide), so the rule is not the whole story (centring rounding or per-glyph exceptions are open).
- Space: 4, 6 and 7 were all worse than 5.

## Hicolor (video mode 3, the default)
Implemented 2026-11-06: `Frame` holds `u16` pixels (palette index or RGB555), `Assets` loads `ICONS3`/`ICONS3B` and the hicolor font when CONFIG.DAT byte 0 is 3 (or `--mode 3`; `--mode 2` forces the 8-bit art). `ICONP6` and `ICONBF1` are 8-bit copies in `ICONS3` and are converted through the palette; any icon that fails to load is converted the same way. Films stay 8-bit.
Start menu against the original in mode 3: 2.31 % of pixels differ (the same text-position residue as in mode 2; backgrounds and frames match). The +1 glyph advance is also the best fit for the hicolor font (0: 3.22 %, 1: 2.31 %, 2: 3.52 %).

## Glyph advance rule (measured, resolved)
On screen every glyph advances `gold-half file advance + 1` px, and the dark half uses the gold half's advance (the file lists one pixel more for a few dark letters such as l, t, u, m, ä), and the space is 6 px (file fix-up 5, plus the same pixel). Found by fitting each glyph's position in the original's captures (`glyphfit.py` approach: dump our glyph positions with `MAD_DUMP_GLYPHS=1`, search each shape near it in the capture). With this rule the Kontor (banner, name line) differs in 53 pixels (0.02 %), start menu 0.55 %, player creation 0.6-1.7 %, rooms 0.1-1.2 %, trade map 0.11 %.
Remaining small residues: justified/centred rounding on a few lines, punctuation before a space, hover colours.

## Capture colour profile (important)
`screencapture` stores the window in the display's profile (Display P3 here).
